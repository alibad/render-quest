# 2026-08-30 — The rest of the roadmap

Seven items were outstanding: three marked `next`, four marked `later`. All seven
are built. The roadmap page now has nothing left on it that is not shipped.

## What we built

**A link that carries the state.** Every lab's controls serialise into the address
bar and restore from it, with a copy button that appears only once something has
actually been moved. Only values that differ from the defaults are written, so a
link says exactly what was changed and nothing else, and the query is sorted so
the same configuration always produces the same URL.

A shared link is user input that reaches a uniform — and, in the instancing lab,
a draw loop. `?count=1e9&mode=per-object` would have issued a billion draw calls
and hung the tab. Values are coerced against the types their defaults imply,
out-of-range ones are rejected by per-lab guards, unknown keys are ignored.

Twelve tests cover the codec, and writing them found a real bug: `?scale=`
parsed as `Number('')`, which is `0` and finite, so an empty value sailed
through as a real setting and would have collapsed the geometry with no error
anywhere.

**A rendering smoke test — the third attempt at one.** Every lab loaded in a real
browser and checked for console errors, for its own failure card, and for whether
the canvas drew anything at all.

The obvious implementation was wrong twice, and only mutation testing found it.
Screenshotting a canvas does not capture WebGL content in headless Chromium at
all; and because this site's body carries a blueprint grid, that grid showed
through the transparent canvas and measured as detail. **The first version passed
with every single lab blanked.** It reads the canvas in the page now, sampling
across frames because a lab's rAF and the sampler's race for position. WebGL
clears its drawing buffer the moment it is composited, so `GLCanvas` takes
`preserveDrawingBuffer` from a flag the test sets before the app loads — off, and
free, in normal use.

Thresholds were calibrated against measurements, not guessed: the first guess
failed two healthy labs. The pipeline lab is legitimately almost monochrome at 19
colours; a blank canvas measures 1.

**Colour & Gamma (lab 8), and the correction it prompted.** A slider splits one
lit sphere down the middle and lights the two halves in different colour spaces —
same geometry, same light, same Lambert term. Plus a grey test: a one-pixel
black/white dither is physically 50% light, and comparing it against `0.5` and
against the correctly encoded 50% is the shortest proof those are not the same
colour.

The correction is the more important half. **Every shader here multiplied
sRGB-encoded values and wrote them straight to the framebuffer** — the most common
bug in real renderers, precisely because it does not look like one. It darkens
midtones and hardens the terminator, which reads as a lighting choice. Fixed in
the shared lit shader and in both of the shading lab's stages; for Gouraud the
encode has to happen after interpolation, or it is a second bug on top of the
first.

**Depth & Transparency (lab 9).** Z-fighting made reproducible from the frustum,
with the arithmetic printed beside the picture so the failure can be predicted
before it appears — set the separation below the resolvable gap and the panels
must fight. Then a transparency scene where depth writing and sorting can each be
switched off to see what each was for.

**The first build of it never actually fought.** The distance control moved the
camera along with the panels, so the view distance was pinned at 14 units however
far away the slider said they were, and the scene was always well inside
precision. Measuring caught it; looking at it did not.

**Write a Shader (lab 10).** An editable fragment shader that recompiles on every
keystroke, with the driver's own error text and the line it objected to
underneath — renumbered past the preamble so it points where you would actually
look. The canvas keeps the last shader that compiled, so a typo leaves your
picture on screen rather than replacing it with black.

**A second reference scene across all four technologies.** The plasma is a
full-screen effect: no geometry, no camera, no depth buffer, and therefore almost
nothing to compare. A lit, depth-tested, spinning cube needs three vertex
attributes, an index buffer, a matrix chain, a normal transform and depth state —
and that list is exactly where the four stop looking alike. Running in WebGL and
WebGPU; code for all four, with both line counts in the comparison table.

**The chooser has its own address.** `/tech/choose`, with its own title,
description and social card, embedded back into `/tech` rather than the other way
round. "Which should I use" is a question people type into a search box.

## What we fixed

- **The shader suite's precision rule was about to produce a false positive.** The
  shader-writing lab supplies uniforms through a preamble, so the preset bodies
  legitimately declare no precision of their own. Rather than loosen the rule,
  the detection was made precise: a literal is exempt only if it declares nothing
  at all AND its file contains a preamble that does declare one. Verified by
  removing `precision` from a real standalone shader and watching it still fail.

## Key decisions

- **Measuring rather than looking, twice.** Both the depth lab and the smoke test
  looked correct on screen and were wrong. Neither would have been caught by
  reading the code or glancing at the render.
- **The smoke test stays out of `npm run build`.** Vercel runs that, and Vercel
  has no browser. It has its own CI job that installs Chromium.
