# The repo went public with no terms, and the README asked you to imagine WebGL

Twelve issues from the backlog, all of them things a stranger hits before they
reach anything the site is actually good at.

## What we fixed

**There was no licence.** The repo went public and `licenseInfo` came back
`null`, which means a lecturer could not legally assign a paragraph — the exact
use the 20,000 words were written for. Now dual-licensed the way the sibling
repo does it: `LICENSE` is MIT for the code, `LICENSE-CONTENT` is CC BY 4.0 for
the prose, figures and curated lists, and it opens by saying plainly which files
fall under which.

`LICENSE` is the plain MIT text and nothing else, deliberately. The first draft
carried a two-line scope note above the body; modelling GitHub's detector
against it scored **92.46% where the threshold is 98%** — the note is a full
sentence, so nothing strips it, and it injects fifteen words MIT does not
contain. The sidebar would have stayed empty. The note now lives in
`LICENSE-CONTENT` and the README, along with the reason it is not in `LICENSE`,
so the next person to notice the gap does not put it back.

**The README had no pictures.** A repo whose thesis is that you cannot see a
motion on a static page was asking a stranger to imagine the one thing it exists
to show. It now opens with three first-party captures, produced by
`scripts/capture-readme-media.ts` from the real site in headless Chromium — the
translate slider dragged out to 1.50 and back with one number in the matrix
moving; the frustum above and the picture it produces below; a shader that will
not compile with the driver's own error reprinted.

The GIF encoder is hand-rolled in the script. Nothing in `devDependencies` can
write a GIF, and GitHub does not autoplay `.webm` in a README — which is the
whole point of the file.

**Three claims in the README were false, and the counts are now tested.** It
said `npm test` runs 69 checks (it runs 89, across seven suites), and that four
technology guides render two identical scenes (two of the four are
`demo: 'code-only'` and the site's own About page already said so).
`test/readme.test.ts` now fails if the lab table, the glossary count, the live-lab
count, the tagline, the site URL or the stated suite count drift from the source.

**Four more pages were making the same wrong claim**, and the new
`test/technologies.test.ts` found them: the home page, the /tech social card,
/about and /tech/choose all told the reader that Three.js and vgpu render. They
now derive the sentence from the registry — `RUNS_HERE` and `CODE_ONLY` — so it
cannot be wrong again without the suite going red.

**The line counts contradicted each other one page down.** /tech printed "24
lines" from a counted figure while /tech/three printed "~24 lines" from a
hard-coded tilde directly above it, and every tilde on the home page was false —
all four plasma figures are counted. There is now one `lineFigure()` helper in
the registry, and a check that no page hand-types a tilde in front of a count.

**The link checker cried wolf and then told nobody.** A single connection failure
marked a link dead; now it retries three times, but only for outcomes that could
change — a 404 is a 404 on the third try too. It distinguishes DNS failure, TCP
timeout, TLS error, 4xx and 5xx, because those mean completely different things.
When the weekly run fails it opens a GitHub issue and updates that same issue
rather than duplicating, and closes it when a run comes back clean.

That machinery immediately earned itself: 3Blue1Brown's host times out at the TCP
level after 25 seconds. It is not a moved URL and swapping it would have been the
wrong fix. The card now says so, and /learn no longer promises "every link is
checked" above its own counter-example.

**A stranger arriving had nowhere to go.** `CONTRIBUTING.md` now says what this
project will and will not accept — raw WebGL and WebGPU, no scene-graph
dependency, no analytics, no cookies, no third-party requests — so nobody spends
an evening on a Three.js pull request. Three issue forms, including one for "this
sentence is wrong", which is this site's most likely inbound report and the one a
generic bug form handles worst. Plus a PR template, a code of conduct, and
Dependabot.

**Also**: a favicon and apple-touch icon that survive 16px, a web manifest,
`npm run lint` in CI, a licence line in the footer, and `"license": "MIT"` in
`package.json`.

## Settings changed outside the repo

Branch protection on `main` (CI must pass, no force pushes, no deletion, admins
exempt so deploy-on-push still works), Dependabot alerts and security updates,
and GitHub Discussions — the issue templates link to it.

## Key decisions

**CC BY 4.0 for the prose, not BY-SA.** The sibling repo uses ShareAlike. The
point here is a lecturer lifting a paragraph into their own slides without
inheriting a share-alike obligation, so the stronger copyleft would defeat the
reason for licensing the prose at all.

**The cube line counts stay estimates.** Deriving them would have printed 21 for
WebGL's cube against Three.js's 24 — the table would have claimed hand-written
WebGL is shorter than Three.js, which is false. The listings are excerpts, so the
estimate says what it excludes instead.

Closes #1, #8, #9, #10, #11, #12, #13, #14, #18, #34, #37, #38, and #4 in
settings.

# Every figure got an address, and the address bar kept losing half of it

Fifteen issues and a feature, applied across all ten essays in one pass, then
gated.

## What we built

**Every figure on the site is now linkable.** All 46 of them carry an id and a
`#` permalink, and the 33 that have a control write that control into the address
bar under the figure's own name — `?rotate.ry=-120`, not `?ry=-120`, so six
figures and the full instrument share one query string without colliding. Until
now the instrument at the foot of the page was the only addressable thing on a
lab, which is the one thing on it that cannot isolate a claim: somebody answering
"why is my normal wrong?" could link to sixteen sliders, or to nothing. `id` is a
required prop, so no figure can ship without one.

**Every lab page shows its contents and what it will cost you.** The section list
and the reading time are parsed out of the essay source at build time rather than
registered anywhere, so renaming a heading renames the link and adding a section
makes it appear. Nobody has to remember.

## What we fixed

**No figure opens at an identity any more.** A figure that opens where its
control does nothing puts a caption about motion under a picture of something
standing still — the colour lab opened at gamma 1.00 with the caption explaining
what happens at 1.00, and the shading lab opened at stretch 1 under a caption
about normals leaning the wrong way. Every opening state is now chosen against
its own caption and the reasoning is written down beside it, including the three
cases where an identity was the right place to open and the reason it is.

**A shared figure link lost its figure.** `useFigureState` was careful to carry
the fragment through its address-bar writes. `useLabState`, which runs on every
lab page whether or not anything is touched, rebuilt the URL from pathname and
search alone — so a reader who opened `/labs/transform?rotate.ry=-120#rotate` was
scrolled to the figure by the browser and then had `#rotate` deleted from the bar
in front of them a tick later. The state survived; the "which figure" half did
not. Nothing looked wrong, because the first arrival always scrolls correctly —
only the link that reader passed on was broken. `test/render.smoke.ts` now cold-
loads a figure anchor on all ten labs and fails if the bar does not still say it.

**Three components hand-typed the repository URL** that `lib/site.ts` already
owns, one of them while importing the constant it was retyping.

**The instrument erased every figure above it.** The other half of the same
seam, found at the gate. `useFigureState` merges — it deletes only the keys under
its own prefix and puts back whatever else it finds — but `useLabState` rebuilt
the query from its own encoding alone, so the first touch of any control in the
instrument deleted `translate.tx`, `rotate.ry` and every other figure key from
the address bar. Measured on eight of the ten labs: move a figure, move the
instrument, and `?translate.tx=-1.5` became `?tx=-1.5`. Nothing looked wrong, for
the usual reason — the figure sliders keep the positions they were restored to,
so every picture on the page stays correct and only the link the reader copies
next is short. The new per-figure copy button made it worse than silent: a button
reading "Copy a link to figure translate in this state" handed over a URL with no
`translate.` key in it at all. `useLabState` now does the merge `useFigureState`
already did, and `test/render.smoke.ts` performs the reader's actual round trip
on every lab — move a figure, move the instrument, require both halves to still
be there.

**Twelve cross-lab references now land on the paragraph they promise.** The
essays point at each other sixteen times, and every one of those links used to
open the target lab at the top of a two-thousand-word essay. Where the referring
sentence cites a specific argument, the link now carries the fragment for the
section that makes it — "the fix is this plane" goes to `/labs/depth#near`, "that
round trip" goes to `/labs/colour#multiply`. Four are deliberately left bare,
because the sentence points at the whole lab rather than at an argument inside
it: two "read this next" pointers, one that simply names the lab, and one that
negates all of it.

**The home page and /labs disagreed about the same ten labs.** `/labs` grew a
read time on each card; the identical grid on the front page did not. Both now
print the same number, from the same cached count.

## Housekeeping

`npm test` runs nine suites now. `test/theme.test.ts` was written but never wired
in, so the check that the canvas palette still matches the CSS tokens it mirrors
was not running; `test/links.test.ts` was written at the end of this batch and
was not wired in either, so nothing was checking that the twelve new fragments
name headings that exist. The README's suite count is checked against
`package.json` rather than typed, and it caught both.

# The batch gate — thirteen issues wired together, and what the wiring found

Ten agents worked on separate file sets and none of them could touch
`package.json`, `app/sitemap.ts`, `components/site/*` or each other's tests. This
is the pass that joined the seams and then tried to break the result.

## What we built

**Three new test suites are actually running.** `test/route.test.ts` (77),
`test/glossary.test.ts` (10) and `test/symptoms.test.ts` (19) were written and
left unwired, which is the same failure `test/theme.test.ts` had two entries ago.
`npm test` is twelve suites now, 263 checks, and the README's suite count is
checked against `package.json` rather than typed — it failed on the way past,
which is the check working.

**/symptoms and /changelog are reachable.** Symptoms leads the header nav;
Changelog sits in the footer between Roadmap and Privacy. Both are in the
sitemap, in the ⌘K index, and in the rendering suite's route list.

**The Atom feed is advertised on every route.** A literal `<link rel="alternate">`
in the root layout rather than `alternates.types`, because Next merges metadata
shallowly and each page replaces the root's `alternates` object whole — the feed
would otherwise have been announced on the home page alone.

## What we fixed

**The sitemap did not type-check.** `app/sitemap.ts` built its dependency-graph
map from an untyped array literal, which widened to `(string | Set<string>)[][]`
and made the intersection's callback parameter `never`. `npx next build` runs
`tsc`, so this would have failed the deploy the moment it was pushed — nobody had
run a build. Fixed by annotating the tuple and rewriting the intersection as a
single `every` pass.

**`twitter:creator` reached one route out of twenty-three.** The plumbing landed
in `lib/site.ts` and `app/layout.tsx`, but the twenty-two pages that call
`pageMetadata()` replace the root's `twitter` object entirely. The spread is now
in `lib/metadata.ts` as well. It still emits nothing until somebody fills in
`AUTHOR_X_HANDLE`, which is the correct behaviour and not an oversight.

## Key decisions

**The feed's `<link>` title is one constant.** `FEED_TITLE` in `lib/changelog.ts`
feeds both the head link and the feed's own `<title>`, because a reader shows one
until it has fetched the feed and the other afterwards, and two names read as two
feeds.

**No unguarded count went into the README.** The shop-window line still reads
"10 labs · 61 glossary terms · 37 resources" with no symptoms count, because
every number in that sentence is checked against a registry and a thirty typed in
beside them would be the one that drifts.
